# CausalGuard

CausalGuard is a foundation prototype for a directed, typed, temporal, privacy-preserving provenance multigraph for agentic AI execution.

The repository provides validated schemas for normalized events, typed nodes, and typed edges; an in-memory `MultiDiGraph` store with export support; and a graph builder that converts normalized traces into causal/control, data/information, and authorization provenance in one connected graph. It intentionally does not include the future trigger-based policy engine or an AgentDojo-specific collector.

## Setup

```bash
python3 -m pip install -e ".[dev]"
```

## Run Tests

```bash
python3 -m pytest -q
```

## Build Test Example Graphs

Generate graph outputs from the JSONL traces in `examples/test_examples/`:

```bash
.venv/bin/python scripts/build_test_example_graphs.py
```

The script writes outputs to `examples/test_examples_output/`:

- `*.graph.json`: typed graph export from `GraphStore.to_json()`.
- `*.graph.dot`: DOT graph source from `GraphStore.to_dot()`.
- `*.graph.mmd`: Mermaid flowchart source from `GraphStore.to_mermaid()`.
- `*.graph.svg`: lightweight SVG visualization generated by the script.
- `*.summary.md`: per-trace node, edge, derivation, and confidence counts.
- `index.md`: summary index of all generated outputs.

Current generated examples:

- `synth_example.jsonl`: 5 events -> 5 nodes, 4 edges, acyclic.
- `exgentic_appworld_07.jsonl`: 60 events -> 59 nodes, 29 edges, acyclic.

Graphviz is not required for this script. The DOT files can still be rendered later with Graphviz if desired, while the SVG files are generated directly.

## Week 1 Scope

- `causalguard/schema/events.py`: normalized collector event schema.
- `causalguard/schema/nodes.py`: five typed graph node schemas.
- `causalguard/schema/edges.py`: typed graph edge schema.
- Strict key-based privacy validation for obvious raw sensitive content fields.

## Graph Store

- `causalguard/graph/store.py`: `networkx.MultiDiGraph` backed typed provenance store.
- Validated node and edge insertion with duplicate, missing endpoint, and cycle rejection.
- Parallel edges are keyed and retrieved by their stable `edge_id`.
- Metadata-preserving JSON export through `GraphStore.to_dict()` and `GraphStore.to_json()`.
- Compact DOT export through `GraphStore.to_dot()` for early graph inspection.

## Graph Builder

- `causalguard/graph/builder.py`: graph builder for normalized event traces.
- Deterministic event-to-node conversion for LLM invocations, tool calls, system operations, data accesses, network sends, human approvals, and device commands.
- Known reads and writes create directionally correct data provenance; explicit result, input, and payload references create `produces`, `input_to`, and `payload_of` edges.
- Destinations remain metadata on system-operation nodes rather than becoming destination data objects.
- Parent-event edges are created with high confidence; same-context fallback edges are created with medium confidence when explicit parent links are absent.
- Scope-matching human approvals create explicit authorization edges to matching tool calls and concrete system operations where the normalized evidence permits it.
- `scripts/build_test_example_graphs.py`: builds JSON, DOT, Mermaid, SVG, and summary outputs for JSONL traces under `examples/test_examples/`.

## Design Decisions

- Pydantic v2 is used for validation.
- Models reject unknown top-level fields so schema drift fails early.
- Timestamps must be finite and non-negative.
- IDs and required string fields must be non-empty after trimming whitespace.
- Privacy validation recursively rejects obvious raw-content keys such as `prompt`, `output`, `message`, `content`, `password`, `token`, `api_key`, `secret`, keys beginning with `raw_`, and keys ending with `_raw`.
- Hashes, stable IDs, labels, scopes, and summaries are allowed.
- The store uses `networkx.MultiDiGraph`; parallel relations retain independent edge IDs and metadata.
- DOT export uses compact node and edge labels and does not include prompt, output, argument, or file contents.
- The builder uses deterministic node IDs derived from event IDs and explicit data references.
- Temporal-window fallback is intentionally not implemented yet; Week 3 only uses explicit parents and shared causal contexts.
- `accesses` remains accepted as a legacy/coarse edge type for imported graphs, but the builder does not emit it when finalized read/write/data-reference semantics are available.
- The test-example graph visualization script is intentionally lightweight and dependency-free; it is not the final visualization layer.

## Normalized Data-Provenance Evidence

The core builder remains framework-neutral. A collector or AgentDojo adapter can attach stable references to a normalized event using:

- `resource_refs` (or legacy `resource_id`) for resources observed by a system operation;
- `result_ref`/`result_refs` or `produced_ref`/`produced_refs` for generated artifacts;
- `input_ref`/`input_refs` for artifacts consumed by an LLM or tool;
- `payload_ref`/`payload_refs` for artifacts explicitly included in a system-operation payload;
- `data_objects` for optional per-reference metadata such as `node_id`, `object_kind`, hash, version, sensitivity, trust, and owner.

The builder never infers data flow merely from a shared session, causal context, or temporal proximity. Parent and causal-context inference remain limited to `invokes` and `triggers` causal edges.

## Assumptions

- Week 1 was schema-only.
- The graph layer records provenance but does not evaluate policy queries.
- Key-based privacy checks are a conservative first guard, not a full content classifier.
- `user_input` events are represented as normalized events and indexed by the builder, but they do not create graph nodes.
- Synthetic traces currently live in tests and `examples/test_examples/`; a mock collector and broader trace-loading workflow are planned for a later milestone.
